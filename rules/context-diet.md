### Delegated exploration and the principal's context diet

**Principle: protect the Anthropic quota by attacking the input context, not the thinking.** The main thread's context is reprocessed on every turn: every file read directly, every verbose output left in the thread, is paid many times. The brain decides the same as always, but operates on short reports, not on whole repositories.

To understand code and plan (not yet edit it), delegate the reading (`haiku` by default; writer executor with thinking if the context exceeds 100K or entire modules must be swallowed; writer-fast as fallback) and do not saturate the principal's context. Delegate when it spans multiple files or it is about flows; read directly if you are going to edit next or it is 1–2 known files. Mandatory return: precise pointers (`file:line`, signatures, snippets, flow), never vague prose. **CodeGraph goes first on both sides:** if there is an index, the principal resolves with ONE call to `codegraph_explore` what would previously have required delegating or reading several files (its output is bounded and does not violate the context diet), and every exploration or scout brief states the index root and says "use `codegraph_explore` before grep/Read". The OpenCode executor (writer executor) has the MCP `codegraph` (tool `codegraph_codegraph_explore`) and the rule in its profile. Same for verbose execution outputs (builds, suites, logs): run and return only the diagnosis.

- **Mandatory pre-distribution scout:** before distributing a phase, a `sonnet` `high` returns the *distribution map*: units of work, file set per unit, applicable conventions/patterns (with `file:line` examples) and existing signatures. The principal decides and stamps the briefs on top of that map — with the served information, each brief costs few lines. **Scout fallback** (quota/billing/rate-limit on `sonnet`): the writer executor with thinking takes the scout. After the writer-executor fallback, the principal **verifies the map** before stamping briefs: context-diet sanity (no whole files dumped) and roster sanity (every unit of work has a responsible engine from the table). Exception: small tasks where the principal already knows the files.
- **Informative questions delegated by default:** when the user asks how something works or where something is (without asking for editing), the investigation is done by `haiku` and the principal synthesises the answer from the report; the principal does NOT read files in the thread to answer questions.
- **Context diet:** the principal does not read full files to plan (it operates on pointers and snippets from reports); outputs from executors go to a file and only the conclusion is read. Direct reading ONLY when the principal is going to edit itself or needs certainty for the reconciliation verdict.
